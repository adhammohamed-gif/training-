# Medical Training Hub

Interactive, chat-style training modules. The home page links to each training; every training has 11 guided sections, follow-up question chips, quick checks, a final assessment and AI answers to typed questions drawn only from that training's content.

**Live site:** https://oab-training.vercel.app (hosted on Vercel; every change pushed to `main` is published automatically within about a minute).

| Training | Path | Content file |
|---|---|---|
| Overactive bladder & mirabegron | `/oab/` | `content/oab.js` |
| Datroway · HR+/HER2− metastatic breast cancer | `/datroway/hr-positive-breast/` | `content/datroway-hr-breast.js` |
| Datroway · first-line metastatic TNBC (not IO candidates) | `/datroway/tnbc/` | `content/datroway-tnbc.js` |
| Datroway · EGFR-mutated NSCLC (US accelerated approval) | `/datroway/egfr-nsclc/` | `content/datroway-egfr-nsclc.js` |

Shared Datroway sections (mechanism, dosing, safety management) live in `content/datroway-common.js` and are reused by all three Datroway trainings.

To view locally, open `index.html` in a browser. Links like `/#trials` from before the home page existed are forwarded to the OAB training.

## Project structure

```
index.html                 Home page (links to every training)
oab/, datroway/*/          Training pages, generated by tools/build_pages.py
assets/styles.css          Visual design (light and dark themes)
assets/app.js              Shared chat engine: navigation, search, quizzes, progress, AI box
content/*.js               Training content, one file per training (+ datroway-common.js)
api/ask.js                 AI answers for typed questions (Vercel Function)
tools/trainings.json       Page settings for each training (titles, footer, scripts)
tools/build_pages.py       Regenerates the training pages from trainings.json
```

## Adding a new training

1. Write `content/<name>.js`, copying the structure of an existing file.
2. Add an entry to `tools/trainings.json`, then run `python3 tools/build_pages.py`.
3. Add the content file to `TRAININGS` in `api/ask.js` so typed questions work.
4. Add a card for it on the home page (`index.html`).

## Updating content

All text, tables, trial data, quizzes and sources live in the training's file in `content/`. Each module is one object:

| Field   | Purpose |
|---------|---------|
| `id`    | Unique slug, also used as the page link (`#id`) |
| `part`  | Sidebar group heading |
| `title` | Sidebar and chip label |
| `intro` | HTML summary shown when the module opens |
| `qa`    | Follow-up questions: `{ id, q, keys, a, tag }` |
| `quiz`  | Quick checks: `{ q, o: [options], c: correctIndex, e: explanation }` |
| `src`   | Sources line shown under the summary |

To add a new trial, add an entry to the `qa` array of the `trials` module with a unique `id` (and, in the OAB training, a short `tag` so it appears in the sidebar trial list). It is then searchable and available to the AI answers.

After any edit:
1. Open the training's page locally and click through the changed section.
2. Add a line to `CHANGELOG.md` (date, what changed, reference used).
3. Have medical/regulatory review confirm the change before release.

## AI answers to typed questions

When a trainee types a question, `api/ask.js` sends it, together with the full module text, to an AI model. The model answers only from that text, keeps figures exactly as written, and returns the section ids it used. These appear as "Source" buttons under the answer.

**AI provider (the first one configured is used):**
1. **Claude API (recommended):** add `ANTHROPIC_API_KEY` in Vercel → Project → Settings → Environment Variables (Production). Optional: `ANTHROPIC_MODEL` (default `claude-haiku-5-5`). The training content is prompt-cached between questions to reduce cost. Set spend limits in the Claude Console.
2. **Vercel AI Gateway:** used when no Claude key is set. Authenticates with the project's OIDC token or `AI_GATEWAY_API_KEY`; optional `AI_GATEWAY_MODEL`. Needs a card on file in Vercel to unlock free credits.

Environment variable changes apply to the next deployment. Redeploy, or push any commit, after adding a key.

- **Fallback:** if the AI service is unavailable (out of credit, offline, or the page is opened as a local file), the box falls back to keyword topic search.
- **Updating:** AI answers read the same content files, so content updates apply to both the guided path and the AI answers. Each training's AI only sees its own content.
- **Review:** AI answers can still misstate or omit details. Trainees are told to check key figures in the linked source sections.

## Migrating to a website later

- **Static hosting** (company web server, Netlify, GitHub Pages, SharePoint): upload the folder as-is; `index.html` (the home page) is the entry point. The guided content works everywhere; the AI answer box needs a server that can run `api/ask.js` (Vercel does this automatically), otherwise it falls back to topic search.
- **LMS (Moodle, Cornerstone, etc.):** zip the folder and upload it as a web package. It is not SCORM-wrapped yet; add a SCORM wrapper if completion tracking in the LMS is required.
- **CMS or app rebuild:** the `content/*.js` files are plain structured data and can be converted to JSON or imported into a CMS without touching the design.

Progress and quiz scores are stored in the viewer's own browser (localStorage). They are not shared or sent anywhere. Central tracking would need a backend or an LMS.
